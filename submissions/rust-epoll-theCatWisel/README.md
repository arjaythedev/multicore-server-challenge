# rust-epoll-theCatWisel

Front: direct

HTTP/1.1 backend written in Rust on top of Linux epoll (`SO_REUSEPORT`) and a custom binary PostgreSQL v3 wire client. Everything in the binary (Linux syscall FFI, HTTP parsing, JSON codec, Base64/Base64URL, SHA-NI / scalar SHA-256, HMAC-SHA256, and multi-lane EksBlowfish bcrypt) is implemented in-tree with zero external crate dependencies (`std` only).

## Design

Four `SO_REUSEPORT` reactor threads run under `SCHED_BATCH`, isolate their kernel file descriptor tables via `unshare(CLONE_FILES)` (bypassing `files_struct` lock contention and `fget_light` atomic refcounting while giving each reactor its own `RLIMIT_NOFILE` table), probe `getrlimit(RLIMIT_NOFILE)` at startup to bound an intrusive $O(1)$ Idle-LRU keep-alive connection pool, and parse HTTP/1.1 requests directly out of a thread-local 256 KiB read buffer whenever a request arrives in one read. Responses are written back with `writev`.

Database work is split across `(cores * 3 / 4).max(2)` read workers (6 on an 8-core host) and `(cores / 4).clamp(1, 2)` write workers (2 on an 8-core host), each holding a single persistent PostgreSQL connection with prepared statements in binary wire format and session-level planner tuning (`plan_cache_mode = force_generic_plan`, `jit = off`, `max_parallel_workers_per_gather = 0`, `work_mem = 32MB`, `random_page_cost = 1.1`, `effective_io_concurrency = 200`):

- Read workers gather batches via a wakeup-suppressed age-bounded queue (`take_aged`) driven by `EWMA_BATCH_LEN` and `BUSY_READ_WORKERS`, and skip requests whose client socket closed while queued via lock-free slot epochs. Each batch executes over reusable byte arenas and reusable `ArrayEncoder` buffers. Phase A is split into two `Sync` sub-pipelines sent in a single `flush()`: Sub-pipeline A1 (`tags`, `uid`, `uemail`) drains first so `GET /api/tags`, `GET /api/user`, and login lookups dispatch immediately to reactor/crypto workers while PostgreSQL executes Sub-pipeline A2 (`prof`, `aslug`, `aid`, `cmts`, `global`, `tag`, `author`, `favlist`, `feed`). List queries that already touch the `articles` heap (`global`, `tag`, `favlist`) project `(slug, title, description, created_at, updated_at)` in Phase A (`MetaSource::PhaseA`), while `author` and `feed` page queries project only `(k, id, author_id)` as index-only scans on `articles_author_idx (author_id, id DESC)` and fetch their metadata once per unique article in Phase B (`artmeta`, without `body`). Phase A also collapses overlapping global article pages (`lim + off <= 200`) into a single B-Tree window scan (`global_win`), materializes prolific-author floor cutoffs on `feed`, and caps `articlesCount` at 1,000. Phase B fetches tags and favorite counts once per unique article (`artx`), resolves author profiles once per unique author (`artau`), and evaluates per-viewer `favorited` and `following` flags via grouped primary-key array lookups (`flags`) with 64-bit viewer bloom masks. Viewer-independent JSON fragments are formatted once into a batch-local byte buffer and unflagged responses within the batch share a single `Arc<[u8]>` payload.
- Write workers execute each batch of mutations inside a single Extended Query Protocol implicit pipeline transaction (committing at `Sync`), grouping concurrent favorite, follow, and comment creation (`newcmt_batch`) operations into `unnest` statements and falling back to per-item execution if a statement fails. Article creation (`newart`) completes directly in the write worker in one round trip, while post-commit favorite and update reads pass `known_fav` to the read queue so Phase B skips redundant `favorites_pkey` lookups.
- Crypto worker threads (`cores.max(4)`) verify and hash passwords in multi-way word-sliced lockstep (`bcrypt_lanes<N>` with 64-byte cache-line aligned `BfState`), auto-calibrating the lane width `N` at startup against the host CPU's L1D cache and register file (`N = 4` on x86-64) and coalescing full `N`-lane batches via `EWMA_BCRYPT_US` and `EWMA_CRYPTO_LEN`. JWT verification reuses precomputed SHA-256 `ipad`/`opad` midstates for the server secret.
