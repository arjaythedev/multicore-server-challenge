# rust-epoll-theCatWisel

Front: direct

HTTP/1.1 backend written in Rust on top of Linux epoll (`SO_REUSEPORT`) and a custom binary PostgreSQL v3 wire client. Everything in the binary (Linux syscall FFI, HTTP parsing, JSON codec, Base64/Base64URL, SHA-NI / scalar SHA-256, HMAC-SHA256, and multi-lane EksBlowfish bcrypt) is implemented in-tree with zero external crate dependencies (`std` only).

## Design

Four `SO_REUSEPORT` reactor threads run under `SCHED_BATCH`, isolate their kernel file descriptor tables via `unshare(CLONE_FILES)` (bypassing `files_struct` lock contention and `fget_light` atomic refcounting while giving each reactor its own `RLIMIT_NOFILE` table), probe `getrlimit(RLIMIT_NOFILE)` at startup to bound an intrusive $O(1)$ Idle-LRU keep-alive connection pool, and parse HTTP/1.1 requests directly out of a thread-local 256 KiB read buffer whenever a request arrives in one read. Responses are written back with `writev`.

Database work is split across `cores.max(4)` read workers (8 on an 8-core host) and 1 write worker, each holding a single persistent PostgreSQL connection with prepared statements in binary wire format and session-level planner tuning (`plan_cache_mode = force_generic_plan`, `jit = off`, `max_parallel_workers_per_gather = 0`, `work_mem = 32MB`, `random_page_cost = 1.1`, `effective_io_concurrency = 200`):

- Read workers gather batches via a wakeup-suppressed age-bounded queue (`take_aged`) driven by `EWMA_BATCH_LEN` and `BUSY_READ_WORKERS`, and skip requests whose client socket closed while queued via lock-free slot epochs. Each batch executes in two pipelined PostgreSQL round trips over reusable byte arenas and reusable `ArrayEncoder` buffers. Phase A deduplicates identical lookups (`unnest(...) WITH ORDINALITY`), collapses overlapping global article pages (`lim + off <= 200`) into a single B-Tree window scan (`global_win`), joins filtered pages by integer ordinal (`int8[]`), materializes top prolific-author floor cutoffs once on `feed` with PostgreSQL `Memoize` caching repeated article primary-key lookups within the statement, and caps `articlesCount` at 1,000 via oldest-first index-only existence checks (`ORDER BY id ASC LIMIT 1 OFFSET 999`). Phase B fetches tags and favorite counts once per unique article (`artx`), resolves author profiles once per unique author (`artau`), and evaluates per-viewer `favorited` and `following` flags via grouped primary-key array lookups (`flags`). Viewer-independent JSON fragments are formatted once into a batch-local byte buffer and unflagged responses within the batch share a single `Arc<[u8]>` payload.
- The write worker wraps each batch of mutations in a single `BEGIN ... COMMIT` pipeline, grouping concurrent favorite, follow, and comment creation (`newcmt_batch`) operations into `unnest` statements and falling back to per-item execution if a statement fails. Post-commit article reads are handed to the read queue so their enrichment shares Phase B with concurrent reads.
- Crypto worker threads (`cores.max(4)`) verify and hash passwords in multi-way word-sliced lockstep (`bcrypt_lanes<N>` with 64-byte cache-line aligned `BfState`), auto-calibrating the lane width `N` at startup against the host CPU's L1D cache and register file (`N = 4` on x86-64) and coalescing full `N`-lane batches via `EWMA_BCRYPT_US` and `EWMA_CRYPTO_LEN`. JWT verification reuses precomputed SHA-256 `ipad`/`opad` midstates for the server secret.
