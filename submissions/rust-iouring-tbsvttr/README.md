# rust-iouring-tbsvttr (Multicore Server Challenge)

Front: direct

Zero-dependency Rust implementation (`[dependencies]` is empty in [`Cargo.toml`](Cargo.toml)) for the RealWorld **Multicore Server Challenge**, built on `tbsvttr`'s shared Rust foundation.

## Architecture & Modules

- **[`src/sys.rs`](src/sys.rs)**: Direct Linux `libc` syscall bindings (`epoll_create1`, `epoll_ctl`, `epoll_wait`, `accept4`, `eventfd`, `getrandom`, `clock_gettime`, `setpriority`, `sched_getaffinity`, `prctl`, `mallopt`), process memory tuning (`PR_SET_THP_DISABLE`, `M_ARENA_MAX = 4`), and TCP socket tuning (`SO_REUSEPORT`, `TCP_NODELAY`, `TCP_DEFER_ACCEPT`, `TCP_QUICKACK`).
- **[`src/buf.rs`](src/buf.rs)**: Zero-allocation byte formatters (`put_int` with a 2-digit lookup table, RFC 8259 `put_json_string`, and `put_timestamp` converting binary PostgreSQL `timestamptz` microseconds since `2000-01-01` UTC into RFC 3339 `"YYYY-MM-DDTHH:MM:SS.mmmZ"`).
- **[`src/json.rs`](src/json.rs)**: Single-pass recursive-descent RFC 8259 JSON validator and zero-allocation field extractor (`valid`, `find`, `object`, `body_object`, `obj_field`, `required`, `next_element`, `decode_string`).
- **[`src/jwt.rs`](src/jwt.rs)**: Pure-Rust SHA-256 with hardware `x86_64` SHA-NI (`sha256rnds2`, `sha256msg1`, `sha256msg2`) acceleration and 16-word rolling scalar fallback, `HMAC-SHA256` with precomputed `ipad`/`opad` SHA-256 midstates (`JwtKey`), `PBKDF2-HMAC-SHA256` (for PostgreSQL `SCRAM-SHA-256` authentication), constant-time `ct_eq`, strict unpadded `base64url`, and zero-allocation per-request HS256 JWT verification (`alg == "HS256"`, `exp > now`, decimal `sub`).
- **[`src/blowfish.rs`](src/blowfish.rs) & [`src/bcrypt.rs`](src/bcrypt.rs)**: Pure-Rust multi-lane interleaved Eksblowfish (`1..=6` lanes, calibrated at startup via `calibrate_lanes`) hashing and verifying up to 6 passwords simultaneously per helper thread so their key schedules share instruction streams inside L1D cache.
- **[`src/pg.rs`](src/pg.rs)**: Pure-Rust PostgreSQL v3 wire protocol client supporting `AuthenticationOk`, `AuthenticationCleartextPassword`, and `AuthenticationSASL` (`SCRAM-SHA-256`), single-round-trip pipelined statement preparation (`s00`..`s21`), and zero-copy binary `DataRow` (`Row`) and `int8[]` (`Int8s`) cursors.
- **[`src/server.rs`](src/server.rs) & [`src/main.rs`](src/main.rs)**:
  - **In-Process Shared-Memory Queues + `eventfd` Wakeups**: Uses in-process thread queues (`WorkerInbox`, `DbInbox`, `BcryptPool`) and coalesced `eventfd` notifications across HTTP workers, the 16-connection PostgreSQL coordinator, and 4 `SCHED_BATCH` multi-lane bcrypt helpers.
  - **Dedicated Set-Based Read Batching (`PAGES` `s08`, `FEED` `s12`, & `COMMENTS` `s19`) + Group-Commit Writes**: Isolates `FEED` (`s12`) into its own set-based batch query (`follows_pkey` -> `articles_author_created_id_desc_idx`) so `PAGES` (`s08`: `LIST_GLOBAL`, `LIST_TAG`, `LIST_AUTHOR`, `LIST_FAVORITED`, `ARTICLE`) executes without fan-out interference, and uses `OFFSET 0` nested `LATERAL` `users_pkey` lookups plus set-based `Hash Semi Join` follow resolution in `COMMENTS` (`s19`).
  - **Once-Per-Batch Pre-Formatted JSON Fragments (`PreTag`, `PreAuthor`, `PreArticle`, `PreComment`) & Viewer-Agnostic Response Reuse**: In `pages_finish` and `comments_finish`, each distinct tag (`k = -2`), author (`k = -1`), article (`k = 0`), and comment (`k = 0`) row returned by PostgreSQL is JSON-escaped, timestamp-formatted, and tag-sorted **once per batch** into a contiguous arena buffer, and identical viewer-agnostic single-article/comment responses within the same batch are deduplicated via open-addressed `IdTable` lookup.
